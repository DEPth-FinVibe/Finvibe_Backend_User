# 로그인/회원가입 구현 가이드

이 문서는 `Finvibe_Backend_User`의 인증/가입 플로우(로컬 로그인 + Google OAuth)를 프론트엔드에서 구현하는 방법을 정리합니다.

## 0) 용어/전제

- **Access Token**
  - API 호출 시 `Authorization: Bearer <accessToken>`으로 전송
  - 응답의 `accessExpiresAt`는 UTC 기준의 ISO-8601 문자열입니다.
- **Refresh Token**
  - Access Token 재발급에 사용
  - 서버는 리프레시 토큰을 저장하며, `/auth/refresh` 호출 시 **로테이션(새 refreshToken 발급)** 합니다.
- **Temporary Token (OAuth)**
  - Google OAuth 로그인 후 “아직 회원이 아닌 사용자”에게 발급되는 임시 토큰
  - `/auth/signup`에 `temporaryToken`으로 전달해 OAuth 가입을 완료합니다.

## 1) 토큰 저장/전송 규칙(권장)

- 토큰 저장소: 앱 구조에 맞게 선택 (예: Web은 메모리 + 새로고침 대비 스토리지, 모바일은 Secure Storage).
- 모든 “인증 필요 API” 요청에 `Authorization` 헤더를 자동 주입합니다.
- **토큰 갱신은 `accessExpiresAt` 기준으로 선제적으로** 수행하는 것을 권장합니다.
  - 현재 구현의 `@AuthenticatedUser`는 토큰 payload를 디코딩해서 사용자 정보를 꺼내는 방식이라, 만료/서명 검증이 강화될 수 있습니다.

### 1-1. 예제 코드 (Axios + 자동 헤더/갱신)

아래는 “최소 동작” 예시입니다(프로젝트에 맞게 상태관리/동시성 처리를 보강하세요).

```ts
import axios, { AxiosError } from "axios";

const API_BASE = import.meta.env.VITE_API_BASE ?? "https://finvibe.space/api/user";

type Tokens = {
  accessToken: string;
  accessExpiresAt: string;
  refreshToken: string;
  refreshExpiresAt: string;
};

let tokens: Tokens | null = null;

export const api = axios.create({ baseURL: API_BASE });

api.interceptors.request.use((config) => {
  if (tokens?.accessToken) config.headers.Authorization = `Bearer ${tokens.accessToken}`;
  return config;
});

async function refreshTokens() {
  if (!tokens?.refreshToken) throw new Error("no refresh token");
  const res = await axios.post<Tokens>(`${API_BASE}/auth/refresh`, {
    refreshToken: tokens.refreshToken,
  });
  tokens = res.data; // refreshToken 로테이션: 반드시 교체
}

api.interceptors.response.use(
  (res) => res,
  async (err: AxiosError<any>) => {
    const status = err.response?.status;
    const code = err.response?.data?.code;
    const original = err.config;

    if (status === 401 && code === "UNAUTHORIZED" && original && !(original as any)._retry) {
      (original as any)._retry = true;
      await refreshTokens();
      return api.request(original);
    }

    throw err;
  }
);
```

## 2) 로컬 회원가입(아이디/비밀번호)

### 2-1. 가입 API 호출

- `POST /auth/signup`
- Body 예시

```json
{
  "loginId": "user1234",
  "password": "pw1234!",
  "email": "user@example.com",
  "birthDate": "2000-01-01",
  "phoneNumber": "010-1234-5678",
  "temporaryToken": null
}
```

주의:
- `loginId`는 `^[a-zA-Z0-9]{4,20}$` 규칙을 만족해야 합니다.
- 현재 구현상 `phoneNumber`가 `null`이면 서버 내부 예외가 날 수 있어 **항상 값을 보내는 것을 권장**합니다.

### 2-2. 가입 성공 처리

응답의 `tokens`를 저장하고, `user.userId`를 필요 시 전역 상태에 저장합니다.

## 3) 로컬 로그인(아이디/비밀번호)

### 3-1. 로그인 API 호출

- `POST /auth/login`

```json
{
  "loginId": "user1234",
  "password": "pw1234!"
}
```

### 3-2. 로그인 성공 처리

- 응답으로 받은 `accessToken/refreshToken`, `accessExpiresAt/refreshExpiresAt` 저장
- 이후 인증 필요 API는 `Authorization` 헤더를 포함해 호출
  - 예: `GET /members/me`

#### 예제 코드 (로그인)

```ts
async function login(loginId: string, password: string) {
  const res = await api.post<Tokens>("/auth/login", { loginId, password });
  tokens = res.data;
}
```

## 4) Access Token 갱신(Refresh)

### 4-1. Refresh API 호출

- `POST /auth/refresh`
- Body 예시

```json
{ "refreshToken": "<refreshToken>" }
```

### 4-2. 갱신 성공 처리(중요)

- 응답의 `refreshToken`은 **새 값으로 교체**합니다(로테이션).
- 실패 시(`401 INVALID_REFRESH_TOKEN`)는 “세션 만료/재로그인” 처리로 전환합니다.

### 4-3. 권장 갱신 트리거

- `accessExpiresAt` 1~2분 전 선제 갱신(네트워크 지연/클럭 오차 대비)
- 또는 API 응답이 `401`이고 `code=UNAUTHORIZED`인 경우(재시도 전략은 앱 정책에 맞게)

## 5) 로그아웃

- `POST /auth/logout` 호출 (인증 필요)
  - Header: `Authorization: Bearer <accessToken>`
- 성공 후 클라이언트 저장소의 토큰을 모두 삭제합니다.

## 6) Google OAuth 로그인/회원가입

이 프로젝트는 Spring Security OAuth2 기본 엔드포인트를 사용합니다.

### 6-1. OAuth 로그인 시작

브라우저/웹뷰에서 아래 URL로 이동합니다.

- `GET /oauth2/authorization/google`

예) `https://finvibe.space/api/user/oauth2/authorization/google`

### 6-2. OAuth 성공 후 프론트로 리다이렉트

OAuth 성공 시 백엔드는 프론트엔드 URL로 리다이렉트합니다.

- Redirect URL: `app.oauth2.base-url`
  - 프론트엔드 OAuth 콜백 URL(현재 서비스 예시)
    - `https://finvibe.space/oauth/callback`
  - 쿼리 파라미터:
    - `registration_required` (boolean)
    - 신규 유저라면: `temporary_token`
    - 기존 유저라면: `access_token`, `refresh_token`, `access_expires_at`, `refresh_expires_at`

프론트는 `/oauth/callback`에서 쿼리를 파싱해 아래로 분기합니다.

예시:

- 신규 OAuth 유저: `https://finvibe.space/oauth/callback?registration_required=true&temporary_token=...`
- 기존 OAuth 유저: `https://finvibe.space/oauth/callback?registration_required=false&access_token=...&refresh_token=...&access_expires_at=...&refresh_expires_at=...`

주의:
- `temporary_token` / `access_token` / `refresh_token`은 **민감 정보**이므로, 브라우저 히스토리/로그/에러리포팅에 남지 않도록 주의하세요.

#### 예제 코드 (OAuth 콜백 페이지에서 쿼리 파싱)

```ts
// 예: https://finvibe.space/oauth/callback?registration_required=false&access_token=... 형태
const params = new URLSearchParams(window.location.search);
const registrationRequired = params.get("registration_required") === "true";

if (!registrationRequired) {
  tokens = {
    accessToken: params.get("access_token") ?? "",
    refreshToken: params.get("refresh_token") ?? "",
    accessExpiresAt: params.get("access_expires_at") ?? "",
    refreshExpiresAt: params.get("refresh_expires_at") ?? "",
  };
  // 예: 로그인 완료 처리(홈으로 이동 등)
} else {
  const temporaryToken = params.get("temporary_token");
  // 예: 추가 정보 입력 화면으로 이동하며 temporaryToken 전달
}
```

#### A) `registration_required=false` (이미 가입된 OAuth 유저)

- 쿼리의 `access_token`, `refresh_token` 등을 저장하고 로그인 완료 처리

#### B) `registration_required=true` (신규 OAuth 유저)

- 쿼리의 `temporary_token`을 저장(짧은 TTL)
- 추가 정보 입력 화면으로 이동 후 “OAuth 가입 완료”를 진행

### 6-3. OAuth 가입 완료(`temporary_token` → `/auth/signup`)

프론트는 추가 정보를 모아서 `POST /auth/signup`을 호출합니다.

- 필수로 준비할 값(권장)
  - `birthDate` (필수)
  - `phoneNumber` (권장: 서버 내부 예외 방지 목적상 사실상 필수로 취급)
  - `temporaryToken` (쿼리의 `temporary_token`)
- 현재 DTO 유효성 검증 때문에 `loginId/password/email`도 비어있으면 `400`이 날 수 있어 **빈 값이 아니게** 전송해야 합니다.
  - 권장: `email`은 소셜에서 받은 이메일 사용, `loginId/password`는 임의 문자열로 채움

Body 예시:

```json
{
  "loginId": "oauth1234",
  "password": "oauth_dummy_password",
  "email": "user@example.com",
  "birthDate": "2000-01-01",
  "phoneNumber": "010-1234-5678",
  "temporaryToken": "<temporary_token>"
}
```

응답으로 `user`와 `tokens`가 오면 토큰 저장 후 로그인 완료 처리합니다.

## 7) 인증이 필요한 API 체크리스트

- 아래 API는 `Authorization: Bearer <accessToken>`이 필요합니다.
  - `POST /auth/logout`
  - `GET /members/me`
  - `PATCH /members/{userId}`
  - `POST /members/{userId}/favorite-stocks/{stockId}`
  - `DELETE /members/{userId}/favorite-stocks/{stockId}`

상세 엔드포인트 목록/스키마는 `docs/API_엔드포인트_정의서.md`를 참고합니다.
